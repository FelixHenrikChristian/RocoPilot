# 本地截图回放

## 原图归档与查找

所有后续用户截图都按用途持续归档，入口为 [素材索引](SCREENSHOT_CATALOG.md)。收到与项目有关的截图时：

1. 将原图原样保存到 `LocalScreenshots/YYYY-MM-DD/<功能>/`，用界面与状态命名；同一原图复用，新版本另存，避免覆盖历史问题现场。
2. 在索引中记录归档路径、附件来源、尺寸、界面状态、用途及已知限制。无法确认的信息明确写出，不凭背景猜精灵名。
3. 需要测试时，从原图派生客户区或控件截图，并记录裁剪坐标、预期结果和测试入口。原图始终保留，避免以后需要其他区域时重新截图。
4. 大图保留在 Git 忽略目录；说明和测试代码纳入版本管理。原图目录不复制到测试输出或应用发布目录。

新对话或修改识别逻辑前先查索引，查看原图和相关测试；只有缺少所需状态时才补充截图。不要批量收集不属于当前对话的临时文件。已经跟踪的 `Fixtures` 历史样本保持原样，不在整理时移除。

常驻精灵的弹窗没有显示精灵名，文件按可核对的场景命名，避免仅凭截图猜测名称。

在仓库根目录运行本地截图回放：

```powershell
dotnet test RocoPilot.Tests/RocoPilot.Tests.csproj -p:Platform=x64 --filter "TestCategory=LocalScreenshots"
```

检查项包括捕捉确认弹窗、左右选中状态、确认按钮位置、点击后的选中状态复查。修改或补充截图后应重新构建，不要使用 `--no-build`，以免读取测试输出目录中的旧文件。日后添加素材时，同时补充文件说明和对应测试预期。
