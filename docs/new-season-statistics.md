# 新赛季统计与归档

## 记录与界面

正式赛季保持现有名称相似度和进化链累计规则。名称暂时未识别时仅在当前战斗继续 OCR，不新增暂存，也不阻塞战斗。

当前本地日期晚于配置中最后一个赛季结束日，统计页新增“新赛季”奇遇卡片和异色子页。右侧奇遇卡片仍按精灵展示累计次数；内部按日期、精确名称／原始 OCR 保存累计桶，不保存逐次奇遇明细。没有精确图鉴匹配时展示 OCR，空 OCR 展示“未识别精灵”。同一战斗后续补读只转移原有的一个计数；已清理的桶不会被迟到 OCR 恢复。

异色仍逐只保存并等待用户确认捕获。临时异色确认后立即记录在临时子页，并清空对应的临时奇遇累计。异色保留原始捕获时间和确认时的累计次数。更新后再确认正式归属时只移动异色，不重复添加，也不再次清零奇遇。

软件启动或同步图鉴只刷新可精确匹配的暂存名称，不自动入账。根据每个计数桶的原始日期推荐赛季，确认窗口按“精灵＋建议赛季”合并；奇遇可修改名称、次数和目标赛季（次数填 0 可清理该组），已捕获异色保留逐只记录，只修改归档名称和赛季。未选择的数据继续保留，未找到赛季时不猜测归属。

确认一次处理所选组的全部来源桶。页面打开后如果对应计数变化，确认失败并提示刷新，避免把新产生的次数一起清掉。批量入账、删除来源和版本递增在同一次统计文档写入内完成；写盘失败不发布内存修改，重试不会重复入账。

## 迁移与清理

当前统计格式为 3.0。旧版未处理奇遇（包含旧版正常赛季的遗留未识别记录）按日累计迁入新流程；新流程不会继续产生正常赛季暂存。旧版已处理奇遇、已处理异色和旧计数重置标记在迁移时删除。仅保留旧字段的读取能力，不再有旧版确认接口或自动补计路径。

正式归档成功后删除对应全部临时桶；空的临时容器及空临时赛季一并移除。名称、OCR、日期、次数、桶 ID、最后写入事件 ID 均不会保留在已处理记录中。

## 云同步版本

沿用现有整账号快照、账号指纹和 ETag 条件上传。使用新流程的账号只增加设备版本向量（每台设备一个递增整数）以及一个升级前账号指纹，不保存每次奇遇或每批入账的历史标记。临时桶仅保存最后一次事件 ID 用于运行时重试，删除桶时一并删除。防重元数据大小与奇遇次数无关；设备 ID 存在本机设置中，导出统计不携带本机设备身份。

比较两端账号版本时，后继版本整体取代旧版本，所以旧云端快照不能恢复已删除暂存，也不能回滚已入账计数。升级前的已知快照通过单个指纹识别；内容不同的旧客户端文档不会被猜测合并。

如果本地仅执行旧格式清理、云端已有正常更新，会用云端仍保留的已处理标记在内存中核对升级前指纹；只有与上次同步基线完全一致，才接收云端更新并继承、递增本地版本。核对副本不持久化；本地实际计数或捕获记录已修改、基线缺失或旧标记无法核对时仍停止同步。

同一账号在两台设备离线各自修改，或旧客户端继续写入导致无法确认先后时，停止本次同步并保留本地和云端原数据。打开云同步窗口点击上传或合并，核对账号的奇遇、异色、暂存和删除状态后，选择“保留本地”或“采用云端”；决议以整个账号为单位，不自动相加另一端的独有内容。取消可先分别导出备份或整理本地数据。确认时重新检查两端是否变化，决议继承双方版本、递增本机版本后上传。旧客户端必须先升级，设备交接应先完成同步再继续记录。完整同步行为见 [Cloudflare R2 同步教程](statistics-sync-cloudflare-r2.md)。

版本向量不按时间过期：删除这些少量数字会失去识别旧快照的能力。其空间按实际使用设备数量增长，不按奇遇数量增长，因此无需逐事件墓碑或历史账本。用户明确删除账号／清空数据仍沿用原有功能。
