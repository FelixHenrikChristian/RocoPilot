# 独立任务的鲁棒性设计

独立任务（邮件、通行证、体力合成、晚风小憩、出售、种菜、花种与传说挑战）靠截图识别加模拟输入推进。
游戏卡顿时点击和按键会偶尔不生效，界面出现的时间也不固定。这份说明约定任务怎样应对，写新任务时照此办理。

## 三层兜底

1. **步骤内补发**。每一步都依据当前画面决定做什么，输入之后由下一步看到的画面确认结果。
   进入新步骤后迟迟等不到预期画面，循环会回到上一步、用当前画面重新判断：目标还在，说明输入没生效，再发一次；
   目标已经不在，说明只是画面慢，继续等。所以不会对着已经变了的界面盲点。
2. **任务级重试**。一步里的时间用完仍没有进展，任务抛出 `TaskStalledException`。
   调度层按 Esc 退回大世界，把这个任务从头再跑 1 次。
3. **清单级隔离**。重试后仍失败，这一项记为失败，每日清单继续执行后面的任务；结束时的汇总和通知会写明哪一项失败。
   只有退不回大世界（例如掉线弹窗）时才终止整张清单，因为后面的任务都要从大世界开始。

## 不会重做的操作

- 出售成交、制造完成、邮件已领取之后，任务把结果记在 `TaskLoop.CommittedOutcome`。之后即使卡在退出界面，
  调度层退回大世界后直接采用这个结果，不会再卖一次、再造一次。
- 挑战类任务卡住时带上已成功的次数（`CompletedRuns`），重试只补剩下的次数。
- 计数型输入（出售时选花的点击）用 `Advance(..., retryable: false)`，由任务自己核对是否生效，不交给循环照原样补发。
- 开关键（M、F2、E、展开列表的三角）补发前等得更久，避免把刚打开的界面又关掉。

## 节奏

常量集中在 `Services/IndependentTasks/Engine/TaskPacing.cs`，任务里不要另写固定等待。

出手之前先看稳：目标要连续可见、点击位置不动满反应时间才发输入。界面刚出来时控件往往还在滑入或淡入，
这时候的点击和按键游戏不认（实测 Esc 菜单滑入途中点邮箱图标，每次都要补点一次）。
目标偶尔一帧认不出来不重新计时；一直在动的目标最多等 2 秒，之后按最新位置出手。

| 项目 | 取值 | 含义 |
| --- | --- | --- |
| 识别间隔 | 150 ms | 两次识别之间的等待 |
| 反应时间 | 500 ms | 目标连续可见且位置不动（6 像素内）满这么久才出手 |
| 输入后等待 | 300 ms | 输入后至少隔这么久再识别 |
| 接受旧帧 | 700 ms | 静止界面不出新帧，输入后超过这个时间就用旧帧判断 |
| 重复按键间隔 | 1.5 s | 同一界面上反复按 Esc、空格 |
| 未知界面兜底 | 3 s | 退出阶段画面一直认不出来时按一次 Esc |
| 点击补发 | 1.5 s 起，每次乘 1.5 | 点击、滚轮、拖动没生效时；补发本身也要先看稳 |
| 按键补发 | 2.5 s 起，每次乘 1.5 | 按键没生效时 |
| 每步补发上限 | 4 次 | 用完后等步骤超时 |
| 任务级重试 | 1 次 | `IndependentTaskService.MaximumTaskRetries` |

连续操作里的后续输入（出售时连点、滚动找花、田里迈步）不等反应时间，传 `react: false`。
种菜在田里的移动、播种仍用原来的间隔（要等角色和镜头停稳），只有地图和种子口袋部分用上表的节奏。

## 退出阶段认不出画面

各任务最后“返回大世界”的步骤里，认得出的界面各有处理（邮箱按 Esc、菜单按 Esc）。
认不出的画面（奖励弹层比预期晚出现、被提示挡住）用 `loop.EscapeUnknownAsync()`：持续 3 秒后按一次 Esc，
不必等到步骤超时再由调度层收场。只在退出步骤里用；流程中途认不出画面时应当等，不要乱按。

## 其他约定

- 游戏窗口不在前台时暂停：不发输入、不计超时，切回游戏后从当前步骤继续。程序不会主动把游戏切回前台。
- 鼠标被别的窗口挡住、光标没移到位这类输入错误不再直接终止任务，下一轮按当前画面重新决定；连续 5 次才算卡住。
- 重跑也没用的失败（目标不在列表里、印记不足、游戏窗口已关闭）仍抛 `InvalidOperationException`，不重试。
- 日志：补发和重试记 WARNING（出了意外但程序兜住了），最终失败记 ERROR。

## 写一个新任务

用 `TaskLoop<TStep>`：`NextFrameAsync` 取帧，`RunStepAsync` 里按 `loop.Step` 分支；
输入用 `loop.KeyAsync / ClickAsync / ScrollAsync / DragAsync`，发出去了（返回 true）再 `loop.Advance`；
输入方法返回 false 多半只是还没看稳，下一轮照常再判断，不要当成失败处理。
同一界面上要反复按的键用 `RepeatKeyAsync`；最后的退出步骤给认不出的画面留一个 `EscapeUnknownAsync`。
每个分支只写“看到什么就做什么”，不要假设上一次输入一定成功，也不要假设界面按固定顺序出现
（领取按钮可能先变灰、奖励弹层过一会儿才出来）。
回放测试里让假游戏忽略第一次输入、让弹层晚一点出现，确认任务仍能跑完。
